# 📌 Repository Guidelines

To ensure consistency, quality, and effective collaboration, all contributors are expected to follow the guidelines below.

---

## 🌿 Branch Naming Conventions
Branch names should reflect the feature or area of the application being worked on and align with high-level implementations.

**Examples:**
- `auth`
- `authentication`
- `video-player`
- `parent-controls`

Use clear, concise, and descriptive names.

---

## ✍️ Commit Messages
- Commit messages must be **clear, concise, and written in English**.
- They should accurately describe the changes made.

**Example:**
- `Add authentication middleware`
- `Fix video playback issue on mobile`

---

## 🔀 Branching & Pull Requests
- All new work must be completed on a **separate branch** (not `main`).
- Once work is complete, submit a **Pull Request (PR)**.
- All PRs will be **reviewed and approved by the repository owner** before merging.

---

## 💻 Code Quality Standards
All contributions must meet the following standards:

- Follow consistent **naming conventions**
- Ensure proper **code formatting and linting**
- Write **clean, readable, and maintainable code**
- Include **unit tests** for new functionality
- Add or update **regression tests** where applicable

---

## 🐞 Issues & Feature Requests
- To report a bug or suggest a feature, please **create a GitHub Issue**.
- Provide clear details, including:
  - Description of the issue or feature
  - Steps to reproduce (for bugs)
  - Expected behaviour

---

## 💬 Communication Channels
Project communication will take place via:
- **Slack**
- **GitHub Discussions**

Please use these channels for collaboration, questions, and updates.
